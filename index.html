1. 서비스 개요

프라임 지분거래소는 부동산 지분(전체가 아닌 일부)을 거래하기 위한 지도 기반 플랫폼입니다. 소액 투자자에게 프리미엄 부동산 투자 기회를 제공하는 것이 목표이며, 사용자 앱·관리자 콘솔·백엔드가 분리된 멀티 레포 구조로 운영됩니다.

🗺️ 지도 중심 UX

Naver · Kakao · VWorld 3개 지도 SDK를 동시 지원하며, 줌 레벨에 따라 시·군·구 → 읍·면·동 → 필지 단위로 데이터 농도가 달라지는 점층적 탐색 구조.

💸 지분 거래

토지·아파트·오피스텔·빌딩·경매·도시개발 등 13개 카테고리 패널로 매물·시세·외부거래 정보를 한 화면에서 조회.

🛠️ 관리자 콘솔

매물 등록/검증·문의·회원·게시글 관리. 네이버 미니맵 기반 좌표 미리보기와 토지 등록 워크플로 제공.

2. 저장소 구성

세 개의 독립 레포가 GHCR(GitHub Container Registry)을 통해 운영 서버에 배포됩니다.

FRONTEND

prime-fe

사용자 프론트엔드 · prime2x.com

  • CRA + React 18
  • Redux Toolkit + SCSS
  • react-router-dom 7 (BrowserRouter)
  • axios · Firebase · Zustand
  • 3개 지도 SDK · 13개 패널
  • 브랜치: master / develop
BACKEND

prime-be

NestJS 백엔드 · :3000

  • NestJS 10 + TypeScript
  • Drizzle ORM + MySQL2
  • Passport (Naver/Kakao/Google/Apple)
  • JWT 인증 + bcrypt
  • RBush 인메모리 공간 인덱스
  • 브랜치: master / develop / baek
ADMIN

prime-fe-admin

관리자 콘솔

  • CRA + React 18
  • Zustand + Tailwind CSS
  • feature-first 폴더 구조
  • 매물 등록/검증 워크플로
  • X-REQUESTED-WITH 헤더 정책
  • 브랜치: main / dev

3. 아키텍처

사용자/관리자 두 프론트가 동일한 NestJS 백엔드를 호출하며, 백엔드는 MySQL의 GEOMETRY 컬럼과 부팅 시 로드되는 공간 인덱스를 활용합니다.

5. DB 스키마

MySQL을 사용하며 Drizzle ORM으로 정의된 스키마는 두 그룹으로 나뉩니다.

▸ 공통 스키마 (drizzle/schema-common/)

테이블주요 컬럼비고
user id, email(unique), password, phone, gender, name, social_naver/kakao/google/apple, status 이메일은 64자 unique. 소셜 연동 여부는 tinyint 플래그
social_account id, user_id, social_user_email, provider, client, social_id, status (provider, client, social_id) 복합 unique. client는 prime 고정

▸ 지역 스키마 (drizzle/schema/)

시·도 단위 17개 테이블이 동일 구조로 정의됩니다.

그룹테이블
수도권seoul · gyeonggi · incheon
충청daejeon · sejong · chungcheongbuk · chungcheongnam
경상busan · daegu · ulsan · gyeongsangbuk · gyeongsangnam
전라gwangju · jeollabuk · jeollanam
강원/제주gangwon · jeju
기타homestead · publichouse · city

각 지역 테이블은 geo (GEOMETRY), point (TEXT), data (LONGTEXT JSON), amount (BIGINT), year/month/day 등을 공통으로 가지며, 공간 질의는 ST_Intersects / MBRIntersects로 수행됩니다. 부팅 시점에 data/polygon/index/*.index.json을 읽어 RBush 메모리 인덱스를 구축합니다.

6. 배포 파이프라인

세 레포 모두 GitHub Actions → GHCR → SSH → docker compose 흐름을 따릅니다.

레포트리거 브랜치이미지서버 경로compose 파일
prime-fe master / develop ghcr.io/return-plus/prime-fe:latest /var/www/html/prime docker-compose.fe.yaml
prime-be master / develop ghcr.io/return-plus/prime-be:latest /var/www/html/prime docker-compose.be.yaml
prime-fe-admin main / dev ghcr.io/return-plus/prime-fe-admin:latest /var/www/html/prime_admin docker-compose.fe.yaml

환경변수는 모두 GitHub Secrets에서 주입됩니다 (DB 자격증명·OAuth 클라이언트·지도 API 키·Firebase·JWT 시크릿 등). 배포 도커파일은 node:20-alpine(FE/Admin) 및 node:22-alpine + pnpm(BE)를 사용합니다.

7. 발견된 이슈 / 의사결정 필요 사항

✅ 관리자 ↔ 백엔드 API 간극 해소 (이 monorepo에서 적용)

prime-fe-admin이 호출하던 누락 엔드포인트를 prime-be에 신규 모듈로 추가했습니다.

  • POST /sign/in · GET /sign/out 구현 완료 — src/sign/
  • POST /land/register · GET /land/table 구현 완료 — src/land/
  • admin 테이블 + AdminJwtGuard + admin 쿠키(admin_action_asid) 분리
  • CORS 허용 origin에 dev 포트(3001/3002) 추가
📝 그 외 관찰 사항 / 해소 현황
  • prime-be 루트의 localhost-key.pem, localhost.pem 개발용 TLS 키 monorepo에서 제거
  • prime-be README 기본 NestJS 템플릿 → 로컬 실행 가이드로 교체
  • prime-fe / prime-fe-admin .env.example 추가 (PORT 3001/3002 분리)
  • prime-fe 디자인 토큰을 CSS Custom Properties로 중앙화 (Tailwind theme 자동 연동)
  • prime-fe-admin의 부동산 매물 데이터는 일부 모킹 상태 (features/property/mocks/) 실 API 연동 필요
  • prime-fe-admin의 인증 만료 정책이 클라이언트 사이드 expiresAt에만 의존 서버 검증 강화 필요
